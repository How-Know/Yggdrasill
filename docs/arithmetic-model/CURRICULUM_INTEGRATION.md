# 교육과정 출제 규칙

교육과정은 덧셈 비용 공식이 아니다. 한 단계가 생성기에 넘길 규칙만 정한다. 학년, 학기, 단원, 성취기준 번호는 코드에 넣지 않는다.

규칙은 `AdditionRule`이다. 스키마는 코드 상수이고 버전은 규칙 필드로 검증한다. 문자열을 실행하거나 SQL로 바꾸지 않는다. 수 비교는 `BigInt`다.

공식 교육과정 표는 아직 없다. 그래서 외래 키 테이블을 만들지 않았다. 등록 전에는 `sourceKind`가 `demo_only`인 예시만 있다.

| id | 예시 |
| --- | --- |
| `demo_sum_at_most_9` | 4+5 허용, 7+8 제외 |
| `demo_sum_equals_10` | 7+3 허용, 4+5 제외 |
| `demo_three_under_10` | 2+3+4 허용, 6+5+1 제외 |
| `demo_two_digit_no_carry` | 23+45 허용, 27+48 제외 |
| `demo_ones_carry_only` | 27+48 허용, 78+57 제외 |
| `demo_two_plus_one_under_100` | 23+4 허용, 98+7 제외 |

교사 화면의 자동 생성은 이 규칙을 자동으로 씌우지 않는다. 교사가 고른 자릿수, 항 개수, 받아올림만 쓴다. 나중에 교육과정을 고르면 같은 `generateAdditionSet`에 `rule`을 넘긴다. 교사 조건이 규칙보다 넓으면 생성하지 않고 이유를 보여 준다. 더 좁히는 것은 된다.

확정된 과제 내용에는 식, 정답, 비용, 시간, 구간, 당시 경계가 들어 있다. 규칙을 나중에 바꿔도 그 과제 문항은 바뀌지 않는다.
