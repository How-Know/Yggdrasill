# 교재 문항 검수 흐름과 기준

- 상태: 사장님 확정 (2026-11-13, 매니저앱 Cursor 대화에서 선택지로 결정, 열린 질문 없음). Think 결정 등록 전
- 결정일: 2026-11-13
- 기억 id: 없음 (Think 등록 후 채운다). 대체하는 결정: 「교재 검수 1단계 범위와 승인·공개 기준」(55074a10, 2026-10-14)의 5번 "수정"

## 배경

- 교재 1권(개념+유형 1-1, 1,915문항)을 끝내고 2권(1-2, 495문항)을 하는 중인데도 소단원마다 수작업과 Cursor 코드 수정이 생긴다.
- 원인: 구현이 처음 정한 흐름에서 벗어났다.
  - AI 수정안을 2단계 도중에 바로 DB(`pb_questions`)에 쓰고 자동 승인한다.
  - 처음 결정은 "AI는 수정안만, 사장님 승인 시 반영"이었다.
  - 문제가 생길 때마다 예외 규칙이 덧붙었다(그림 크기 차이는 준비됨에서 제외, 엔진 보류 승인 예외 등).
- 1-2는 79%(389문항)가 AI 수정 반영을 거쳤고, 그중 305문항이 그림 크기·배치 수정이다. 렌더 검수는 문항 2,410개에 1,491회, 수정안은 1,178회 돌았다.
- 이 문서는 처음 기준을 다시 적고, 그 기준을 구현할 때의 세부를 확정한다. 기준 자체를 바꾸지 않는다.

## 결정

### 1. 목적
1. 사장님이 문항을 하나하나 검수하지 않도록 AI가 검수한다.
2. 앞으로 새 교재는 본문 추출과 검수를 한 번에 진행한다. 본문이 이미 추출된 교재는 검수만 돌린다.

### 2. 검수 기준 (세 축을 따로 판정, 2026-10-14 기준 유지)
1. **원본 충실도**
   - 문항, 정답, 해설 연결이 맞다.
   - 원문의 수식, 조건, 그림을 빠짐없이 옮겼다.
   - 크롭에 같은 쪽의 정답이나 해설, 다른 문항, '해' 풀이 안내가 섞이지 않았다.
   - 공통 지문이 잘리지 않았다.
2. **수학적 타당성**
   - 정답이 맞다.
   - 해설은 원본을 빠짐없이 전사했는지와 해설 논리에 오류가 있는지까지 본다. 정답 일치만으로 해설을 승인하지 않는다.
   - 교재 원본 자체의 오류로 보이면 원본은 보존하고 교정 의견을 남긴다. 사장님이 처리하기 전까지 그 문항은 준비됨이 아니다.
3. **출력 품질**: V2 A4에서 그림, 수식, 배치가 제대로 보인다.
4. **그림 크기**
   - 원본의 글자 대 그림 비율이 V2의 글자 대 그림 비율과 같아야 한다.
   - 차이가 ±10%를 넘으면 자동 조정 대상이다.
5. **그림 위치**
   - 원본과 같게 둔다. 글의 오른쪽, 왼쪽, 아래를 맞추고, 아래일 때는 왼쪽·가운데·오른쪽 정렬까지 맞춘다.
6. **해설 그림**: 문항 그림과 같은 기준(크기 비율, 위치)을 적용한다.

### 3. 문항 메타 정보 (필수)
1. 필수 항목은 다음과 같다. 하나라도 비어 있으면 준비됨이 아니다.
   - 개념 연결(개념 라이브러리의 개념)
   - 사고 코드
   - 난이도 3축(개념, 사고, 계산 점수)
   - 시각 태그
   - 문항 유형(객관식/주관식/서술형)
   - 교재 원본 라벨(번호 옆의 대표유형, 상중하, 서술형 등)
2. AI가 제안하고, 사장님은 필요할 때만 고친다. 확정할 때 함께 반영한다.
3. 확정된 메타 정보는 문제은행 문항에도 반영한다. 문항 검색, 통계, 출제에서 쓰기 위해서다.
4. 맞는 개념이 라이브러리에 없으면 AI가 새 개념 초안을 제시한다. 소단원 확정 때 그 개념을 라이브러리에 바로 만들고 문항을 연결한다.
5. 빈 값 판정 (2026-11-13 추가 확정)
   - 교재 원본 라벨: 크롭 확정 때 사장님이 문항 번호·본문과 함께 확인한다. 검수 단계에서 빈 라벨은 "라벨 없음"으로 보고 막지 않는다.
   - 시각 태그: 시각 요소가 없으면 AI가 "없음" 태그를 고른다. "없음"은 다른 태그와 함께 두지 않는다. 빈 태그는 누락이다. 1-1과 1-2의 빈 태그 문항은 메타 전용 AI 실행에서 다시 고른다.
   - 계산 점수: AI 풀이를 거친 뒤 0이면 "계산 없음"으로 보고 유효한 값으로 둔다.

### 4. 흐름과 반영 시점
1. 흐름: 소단원 선택 → 이어서 마무리(새 교재는 추출 + 검수) → AI가 검수하고 수정안을 만듦 → 결과 보고 → 사장님 확정 → DB 일괄 반영.
2. **2단계는 수정안만 만든다.** 문제은행 문항과 정답에 쓰지 않는다. 렌더 검수는 수정안을 반영한 V2를 그려서 원본과 대조한다(DB 쓰기 없이).
3. AI 수정안 → V2 재렌더 → 원본 재대조는 문항당 최대 2회다. 그래도 남으면 사장님 확인으로 넘긴다.
4. 결과 보고
   - 모든 문항이 준비됨이면 "준비됨 N"을 표시한다.
   - 아니면 "준비 15/17"처럼 표시하고, 상세는 작업 화면에서 문항별로 막힌 이유를 보인다.
   - 막히는 경우: 코드(렌더 엔진) 수정 필요, 수정 권한 없음, 판정 기준이 모호함, 교정 의견 처리 필요, 메타 정보 누락.
5. 확정 전에 사장님이 작업 화면에서 고친 내용(본문, 정답, 그림 배치, 메타 등)도 수정안으로 쌓아 두고, 확정 때 함께 반영한다.
6. 렌더 엔진(코드) 수정이 필요한 문항이 남아 있으면 소단원 확정을 막는다. 코드를 고치고 재확인한 뒤 확정한다.
7. 확정 = 검수 완료 표시와 DB 일괄 반영이다. 학습앱 노출은 지금처럼 책 단위 숨김으로 따로 관리한다.
8. 확정 뒤 사장님이 따로 고친 문항은 검수가 틀렸던 것으로 본다. 사장님 수정이 덮어쓰고, 검수됐다는 기록은 그대로 둔다. 확정 전에는 다른 경로로 문항이 바뀌는 일이 없다(1차 추출과 검수를 함께 진행).

### 5. 이미 처리한 교재(1-1, 1-2)
1. 이미 DB에 반영된 내용은 그대로 둔다.
2. AI 비용이 없는 코드 정합성 점검을 돌린다. 걸린 문항만 수정안으로 만든다.
   - 그림 개수와 `[그림]` 자리 불일치
   - '해' 안내 잔여
   - 수식 구분자 오류
   - 정답 불일치 등
3. 비어 있는 메타 정보는 메타 전용 AI 실행으로 제안을 만들고, 소단원별 확정 때 반영한다.
4. 예전 흐름에서 검수를 마쳐 승인된 문항(검수됨·확정)은 승인 당시의 그림 크기 판정(±15%)을 인정하고 그림을 다시 조정하지 않는다. ±10%는 새 흐름으로 검수하는 문항에 적용한다. (2026-11-13 추가 확정)
5. 본문만 추출하고 검수하지 않은 소단원(완료됨)은 재검수가 아니므로 새 흐름으로 검수한다. (2026-11-13 추가 확정)
6. 1-1과 1-2의 기존 개념 태그는 잘못된 후보 목록(개념 테이블 앞쪽 80개)에서 고른 것이라 근거로 쓰지 않는다. 메타 전용 AI 실행으로 전 문항의 개념 태그를 다시 제안하고, 소단원 확정 때 그 값으로 반영한다. 개념 후보는 같은 학년 개념서(개념 출처)의 같은 단원 개념이다. (2026-11-13 추가 확정)

## 이유
- 처음 결정과 구현이 어긋나서 예외가 쌓이고, 같은 문제가 반복됐다. 기준을 다시 세우는 것보다 처음 기준대로 되돌리는 것이 맞다.
- 반영을 확정 한 번으로 모으면, 사장님이 보는 결과와 DB에 들어가는 결과가 같아진다.
- 재대조 횟수를 2회로 제한해 같은 문항에 비용이 반복해서 나가는 것을 막는다.

## 검토한 대안
- 준비됨 조건을 줄이기(배치 차이는 기록만): 처음 정한 기준(그림 위치는 원본과 동일)과 다르므로 채택하지 않음.
- AI 자동 반영 유지: 처음 결정과 다르므로 채택하지 않음.
- 1-1과 1-2를 새 흐름으로 다시 검수: AI 비용이 다시 들어 채택하지 않음. 정합성 점검과 메타 보충만 한다.
- 확정한 소단원만 학습앱에 노출: 채택하지 않음. 노출은 책 단위 숨김으로 관리한다.

## 구현 범위

### 해야 할 것
1. 2단계 파이프라인(`textbook_review_pipeline.dart`)과 작업 화면의 자동 반영을 걷어낸다. 걷어낼 경로는 `_applyPendingProposals`, 일괄 수정, `approveAxis` 자동 승인, 그림 자동 크롭·업로드다. 수정안만 저장한다.
2. 렌더 검수가 수정안을 반영한 문항 데이터로 V2를 그리게 한다(`/pb/preview/custom-thumbnail`처럼 DB 쓰기 없이).
3. 소단원 확정 때 수정안을 일괄 반영한다.
   - 반영 대상: 본문, 선지, 공통 발문, 그림 배치, 원본 그림 크롭, 정답, 해설, 메타 정보, 새 개념 생성과 연결.
   - 실패한 문항은 반영하지 않고 확정을 멈춘다.
4. 준비됨 판정을 위 기준으로 정리한다.
   - 그림 크기는 글자 대 그림 비율 ±10%로 판정한다.
   - 그림 위치와 정렬, 해설 그림, 교정 의견, 메타 필수 항목을 넣는다.
   - 그림 크기 예외 같은 덧붙인 예외는 뺀다.
5. 메타 정보: 교재 원본 라벨 추출과 제안을 넣고, 확정 때 문제은행 문항에 반영한다.
6. 코드 정합성 점검(AI 없음)을 만들어 1-1과 1-2에 돌리고, 걸린 문항을 수정안으로 만든다. 규칙을 바꿀 때마다 다시 돌린다.
7. 메타 전용 AI 실행으로 1-1과 1-2의 빈 메타를 제안한다.
8. 회귀 세트: 지금까지 고친 사례(p.41 1·7·8·15·27, p.44 01, p.46 01, P31 등)로 카드 렌더와 PDF 내보내기 컴파일을 자동 확인한다.
9. 새 교재 시작 전 지면 형식 점검 단계를 둔다.
10. 원인별 수작업 집계를 표시한다(새 형식, 옛 데이터, 엔진 버그, AI 오판정).
11. 해설·해설 그림·메타를 문제은행 문항 쪽 저장 위치로 옮기고, PDF 내보내기와 정답·해설 카드가 그쪽을 읽게 바꾼다. 1-1과 1-2의 기존 값도 옮긴다.
12. 확정 때 만드는 새 개념에 "교재 검수에서 생성" 표시를 남긴다.

### 하지 않을 것
- 검수 기준을 바꾸거나 준비됨 조건에 예외를 덧붙이지 않는다. 바꿔야 하면 이 문서를 먼저 고친다.
- 1-1과 1-2를 전면 재검수하지 않는다.
- 확정한 소단원만 노출하는 방식을 만들지 않는다.

## 지켜야 할 철학·원칙
- 교재 원본은 바꾸지 않는다. 원본 오류는 교정 의견으로 남긴다.
- 사람이 고친 값은 AI 재실행이 덮어쓰지 않는다.
- OpenAI 호출은 Edge Function에서만 하고, `ai_runs`에 기록한다.
- 학생은 검수 데이터에 접근하지 못한다.
- 결정과 다르게 구현해야 하면 코드를 먼저 바꾸지 않고, 이 문서와 Think 결정을 먼저 고친다.

## 완료 조건
- 2단계를 끝까지 돌려도 `pb_questions`와 정답 테이블이 바뀌지 않고, 확정을 눌러야 바뀐다.
- 준비됨 판정이 위 기준만으로 정해지고, 기준 밖 예외가 없다.
- 확정 때 메타 정보가 문제은행 문항에 들어가고, 새 개념이 만들어져 연결된다.
- 1-1과 1-2 정합성 점검 결과와 걸린 문항의 수정안이 있다.
- 회귀 세트가 테스트로 돌고, 카드 렌더와 PDF 컴파일이 통과한다.

### 6. 데이터 위치 (2026-11-13 추가 확정)
1. 확정된 해설(원본 해설 전사, 해설 정답), 해설 그림, 메타 정보는 문제은행 문항 쪽으로 옮긴다. PDF 해설 섹션, 정답·해설 카드, 검색·통계·출제는 문제은행 쪽만 읽는다.
2. 검수 테이블(`textbook_problem_analyses`)은 삭제하지 않고 작업 기록용으로만 남긴다. 남는 것은 수정안, 렌더 판정, 엔진 보류, AI 풀이 같은 검수 과정 기록이다.
3. 이미 처리한 1-1과 1-2의 해설·해설 그림·메타도 같은 위치로 옮긴다(AI 비용 없음).

### 7. 새 개념 승인
1. 소단원 확정을 그 소단원에서 제안된 새 개념의 승인으로 본다. 개념 라이브러리 카드 승인을 따로 거치지 않는다.
