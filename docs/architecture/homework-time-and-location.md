# 과제 학습 시간과 수행 장소

학생앱을 집에서도 쓰게 하면서 생긴 질문 하나 — **같은 30분이 학원에서 나온
것인지 집에서 나온 것인지 어떻게 아는가.** 이 문서는 그 답과, 하원을 하루의
마디로 삼는 규칙을 정리한다.

## 한눈에

| 규칙 | 내용 |
|------|------|
| 수행(타이머) | 학원·집 어디서나 가능 |
| 채점 | 학원·집 모두 가능 (자동 채점 포함) |
| 제출(검사 요청) | **등원 중에만** |
| 하원 | 타이머 강제 정지 + 모든 과제 대기(1)로 |
| 시간 기록 | 구간 단위로 남기고 학원/집을 구분 |

## 왜 이렇게 했나

제출은 "선생님, 검사해 주세요"라는 뜻이다. 집에서 밤에 눌러도 검사는 학원에서
이뤄지므로, 등원 중에만 받는 편이 상태와 현실이 어긋나지 않는다. 대신 하원할 때
모든 과제를 대기로 되돌려 두면, 집에서 이어서 더 풀고 다음 등원 때 제출하는
흐름이 자연스럽게 만들어진다. 교재 제출 잠금(`book_submitted`)도 이때 함께
풀리므로 집에서 계속 풀 수 있다.

## 시간은 구간으로 남는다

`homework_items.accumulated_ms` 는 누적 카운터 하나뿐이라 장소를 담을 수 없었다.
그래서 `homework_study_intervals` 를 두고 수행 구간을 한 줄씩 남긴다.

| 컬럼 | 뜻 |
|------|-----|
| `started_at` / `ended_at` | 구간의 시작과 끝 (`ended_at` 이 null 이면 진행 중) |
| `duration_ms` | 마감 시 계산 |
| `location_kind` | 구간을 열 때의 출결로 판정 (`academy` / `home`) |
| `last_beat_at` | 학생앱이 마지막으로 살아 있다고 알린 시각 |
| `closed_reason` | `pause` / `departure` / `relocate` / `stale` / `cleanup` |

기록은 **RPC 가 아니라 트리거**가 한다. `homework_items.run_start` 가 켜지고
꺼지는 순간을 `trg_homework_items_track_run` 이 잡으므로, 학생앱·매니저앱·M5·
하원 처리 어느 경로로 들어와도 구간이 남고 새 RPC 가 생겨도 손볼 필요가 없다.

조회를 위해 `homework_items.academy_ms` / `home_ms` 에 구간 마감 시 합계를
쌓는다. 이 둘은 **실측값**이라, 그룹 사이클 4→1 에서 문항 수 비례로 재분배되는
`accumulated_ms` 와 정확히 일치하지 않을 수 있다. 장소 비율을 보는 용도다.

### 등원 순간의 분할

집에서 타이머를 켠 채 등원하면 그 구간 전체가 `home` 으로 남는다. 그래서
등원(`arrival_time` 확정) 시 `_homework_relocate_intervals` 가 구간을 끊고
새 위치로 다시 연다. 타이머와 단계는 건드리지 않는다.

## 하원 = 하루의 마디

`trg_homework_reset_on_departure` (attendance_records 의 `departure_time` 이
처음 채워질 때):

1. 열린 구간을 하원 시각으로 마감 (`departure`)
2. 돌던 타이머를 하원 시각까지만 누적하고 정지
3. 완료되지 않은 과제를 **단계와 무관하게** 전부 대기(1)로 — 제출(3)·확인(4) 포함
4. `homework_group_runtime` 도 같은 상태로 정렬

이전에는 이 정리가 매니저앱 하원 처리와 PC 알림장 인쇄 워커 안에만 있어서,
키오스크로만 하원하면 타이머가 집에 가서도 돌았다. 이제 경로와 무관하게 같다.

학습 세션(`learning_sessions`)도 하원 시 닫는다. 열린 세션은 12시간 안이면
재사용되므로, 닫지 않으면 집에서 이어 푼 기록이 학원 세션에 섞인다.

## 앱이 죽으면

수행 중일 때 학생앱이 **30초마다** `student_homework_beat()` 를 부른다. 서버는
열린 구간의 `last_beat_at` 을 갱신한다. 앱이 갑자기 죽어도 마지막 신호까지는
학습 시간으로 남으므로, 손실 상한이 30초다.

문제는 iOS 가 **백그라운드 중단과 강제 종료를 구분해 주지 않는다**는 점이다.
잠금화면에서 라이브 액티비티로 계속 공부하는 흐름을 살리려면 신호가 끊겼다고
바로 멈출 수 없다. 그래서:

- 백그라운드로 내려가는 순간 신호를 한 번 더 찍는다.
- 그 뒤로는 계속 수행 중으로 둔다.
- 복귀했을 때 **라이브 액티비티가 사라져 있으면** `student_homework_rewind()`
  로 마지막 신호 시점까지만 인정하고 멈춘다.
- **3시간** 넘게 신호가 없으면 `homework_sweep_stale_runs()` 가 마지막 신호
  시점으로 마감한다. 이 스윕은 누구든 신호를 보낼 때 함께 돌아서 별도
  스케줄러가 필요 없다.
- 하원하면 어차피 강제로 끊긴다.

## 제출 차단

서버 `student_group_transition(p_from_phase = 99)` 가 등원 여부를 보고
`{ok: false, error: 'not_at_academy'}` 를 돌려준다. 요청 ID 를 소모하기 전에
막으므로 재시도가 막히지 않는다.

학생앱은 미니바·시트·잠금화면의 제출 버튼을 흐리게 표시하고, 눌러 보면 이유를
알려준다. 죽은 버튼은 고장으로 오해하기 때문이다. 판정 기준은 서버와 같다
(`StudentAttendanceSession.isAtAcademy` ↔ `_student_location_kind`).

## 남은 것

iOS 라이브 액티비티는 코드가 다 있지만 **Xcode 위젯 익스텐션 타깃이 아직
추가되지 않았다**. `apps/yggdrasill_student/ios/HomeworkLiveActivity/XCODE_SETUP.txt`
절차를 맥에서 한 번 해야 잠금화면에 뜬다. 그 전까지 "라이브 액티비티가 사라지면
되감기"는 동작하지 않고, 3시간 상한과 하원 마감만 걸린다.
