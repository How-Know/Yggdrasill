## 변경 목적

출석 점수와 과제 수행도에 비례하는 누적 재화(포인트)를 도입한다. 이후 아이템 상점,
감점 요소, 레벨 시스템, 게임 확장으로 이어질 기반이므로 되돌리기 어려운 부분을
먼저 확정하는 데 목적이 있다.

1단계 범위는 **원장 + 적립**까지다. 소비(아이템 상점/구매)는 발행량을 관찰한 뒤
2단계에서 도입한다.

## 변경 전

- 포인트 개념 없음. 출석 점수(v4.1)와 과제 점수(v1)만 실시간 계산해 표시.
- 두 점수는 모두 시간 감쇠가 있어 과거 값이 계속 변한다.

## 변경 후

### 핵심 원칙

1. **원장이 유일한 진실.** `student_point_ledger`는 append-only이며 UPDATE는 트리거로
   차단된다. 정정은 수정/삭제가 아니라 `reversal` 반대 거래로 남긴다.
   `student_point_balances`는 파생 캐시이고 원장 INSERT 트리거로 갱신된다.
2. **지급 시점 확정(스냅샷).** 점수는 감쇠하지만 포인트는 발생 시점 값으로 확정한다.
   계산 근거는 `basis` jsonb에 저장하고, 이후 규칙이 v2로 바뀌어도 과거 지급분은
   재계산하지 않는다.
3. **멱등.** `(academy_id, student_id, season_id, kind, source_type, source_id)` 유니크로
   같은 출석/과제에 대한 중복 지급이 물리적으로 불가능하다. 호출 측에서 중복 검사를
   하지 않아도 된다.
4. **누적과 잔액 분리.** `lifetime_earned`는 레벨/등급 기준값이라 소비해도 줄지 않고,
   `balance`만 소비로 줄어든다.
5. **시즌 대비.** `season_id`를 미리 두고 현재는 sentinel(`0000...0000`) 단일 시즌만 쓴다.

### 지급 규칙

**출석 (앱에서 지급)**

- 대상: 실제 출석이 확정된 기록만. `is_present` 또는 등/하원 시각이 있는 경우.
  예정(planned) 행과 결석은 지급하지 않는다.
- 기본값: 정시 출석 `20`, 지각 `12`
- 배수: `0.8 + (출석점수/100) * 0.4` → `0.8 ~ 1.2`
- 지급액: `round(기본값 × 배수)` → 정시 `16~24`, 지각 `10~14`
- 멱등 키: `attendance_record.id`
- 지급 위치: `AttendanceService.saveOrUpdateAttendance` 종료 시점
  (출석 점수와 지각 기준이 앱에만 있으므로 DB에서 계산하지 않는다)

**과제 완료 (DB 트리거에서 지급)**

- 대상: `homework_items.status`가 완료(1)로 전이될 때
- 기본값: `10`
- 시간 보너스: `min(누적분/90, 1.0) × 6`
- 검사 보너스: `min(검사횟수/5, 1.0) × 4`
- 지급액: `round(10 + 시간보너스 + 검사보너스)` → `10~20`
- 멱등 키: `homework_item.id`
- 지급 위치: `trg_homework_items_grant_points` 트리거
  (품질 지표가 DB에 있고, 학생앱 완료 경로도 함께 커버해야 하므로)

### 보안 경계

- `_point_grant_internal`: 내부 전용. 클라이언트 실행 권한 없음.
- `point_grant_v1`: 공개 RPC지만 호출자의 `memberships` 존재를 요구한다.
  학생 계정이 임의로 포인트를 발행할 수 없다.
- 두 테이블 모두 RLS는 `memberships` 기반이므로 학생앱에서 직접 조회/수정할 수 없다.
  학생앱 노출은 별도 `student_app_identity()` 기반 RPC를 추가할 때 열린다.

### 어뷰징 차단

- 과제 검사 보너스는 5회에서 상한이므로 반복 검사로 무한 파밍되지 않는다.
- 시간 보너스는 90분에서 상한이므로 타이머를 켜두는 것으로 무한 가산되지 않는다.
- 하원 처리 등으로 같은 출석 행이 여러 번 저장되어도 유니크 제약이 1회로 막는다.

## 영향 범위

- 서비스: `PointService` 신규. `AttendanceService`에 지급 훅 1곳 추가(실패해도 출석 저장은
  롤백하지 않는다).
- DB: 테이블 2개, 함수 4개, 트리거 3개 신규. 기존 `homework_complete` RPC는 수정하지 않았고
  상태 전이 트리거로 대신 잡는다.
- UI: 학생 스탯 탭에 `포인트` 섹션 추가(잔액, 누적 획득, 사용, 적립 건수, 누적 기준 순위).
- 순위: 잔액이 아니라 누적 획득 기준. 소비가 순위를 깎으면 소비를 억제하게 되므로 배제.

## 발행량 추정

학생 80명, 주 2회 수업, 수업당 과제 4~5개 기준.

- 출석: 주 2회 × 약 20P = 약 40P/주
- 과제: 주 8~10건 × 약 14P = 약 112~140P/주
- 학생 1인 합계: 약 150~180P/주

아이템 가격은 이 발행량을 4주 이상 관찰한 뒤 결정한다. 원장 구조이므로
`kind`별 주간 합계로 발행량(faucet)과 소모량(sink)을 바로 집계할 수 있다.

## 롤백 기준

- 발행량이 예상의 2배를 넘거나 특정 경로에서 중복 지급이 확인되면 지급 훅만 먼저 끊는다
  (`_grantAttendancePointsIfEligible` early return + 트리거 drop).
- 원장 데이터는 삭제하지 않는다. 필요 시 `reversal` 거래로 정정한다.
